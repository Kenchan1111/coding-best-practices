# Dict_AI_Coding Generated Artifacts Map

## Goal

Distinguish important generated evidence from rebuildable cache output, and
show which generated surfaces are part of the live workflow versus future
cleanup machinery.

## Artifact Classes

- `protocol_evidence`: generated and kept because a workflow depends on it.
- `managed_projection`: generated by synchronization from another
  authoritative note.
- `derived_summary`: generated summary used for navigation or coordination.
- `runtime_state`: mutable local process/service state.
- `compiled_noise`: rebuildable bytecode and caches.

## Change-Proof Artifacts

### Local change sessions

Pattern:

- `change_sessions/<session_id>/session.json`
- `change_sessions/<session_id>/task_snapshot.md`
- `change_sessions/<session_id>/closeout_template.md` when rendered
- `change_sessions/<session_id>/closeout.md` when sealed
- `change_sessions/<session_id>/closeout.md.change-receipt.json` when sealed
- `change_sessions/<session_id>/change_receipt.json` when emitted

Classification:

- `protocol_evidence`

Producer:

- `repo-change-guard`

Consumer:

- human reviewers
- cleanup and audit work
- future handoff notes when closeout evidence is referenced

Important note:

- the root `change_sessions/` is local-only by policy and can grow during
  ordinary work; cleanup must expect drift until manifests are rebuilt

### Historical MCP proof

Pattern:

- `mcp/repo-change-guard/<session_id>/session.json`
- `mcp/repo-change-guard/<session_id>/task_snapshot.md`
- `mcp/repo-change-guard/<session_id>/closeout.md`
- `mcp/repo-change-guard/<session_id>/closeout.md.change-receipt.json`
- `mcp/repo-change-guard/<session_id>/change_receipt.json`
- `mcp/repo-change-guard/<session_id>/p7-e2e-proof/*` when present

Classification:

- `protocol_evidence`

Producer:

- prior `repo-change-guard` runs

Consumer:

- reviewers
- future worktree cleanup audits
- historical proof lookups

## Review-Proof Artifacts

Pattern:

- `review_sessions/<review_session_id>/session.json`
- `review_sessions/<review_session_id>/snapshot.md`
- `review_sessions/<review_session_id>/review_template.md`
- `review_sessions/<review_session_id>/review_receipt.json`

Classification:

- `protocol_evidence`

Producer:

- `repo-review-snapshot`

Consumer:

- review authors
- sync/audit workflows

Important note:

- `review_sessions/` is already part of the local-only policy, but the
  directory may legitimately not exist yet

## Review Bus Projections

### Source-note receipts

Pattern:

- `reviews/<agent>/<kind>/*.md.receipt.json`

Classification:

- `protocol_evidence`

Producer:

- review sealing/snapshot tools

Consumer:

- sync validation
- review audit

### Global and peer copies

Pattern:

- `reviews/global_handoff/*.md`
- peer `reviews/<agent>/handoff/*.md` with `sync_managed_copy: true`

Classification:

- `managed_projection`

Producer:

- `scripts/sync_reviews.py`
- `scripts/sync_reviews_watch.py`

Consumer:

- peer agents
- humans browsing the shared handoff bus

Important behavior:

- source notes are never overwritten
- same-name/different-digest collisions create explicit variants
- managed copies carry source path and digest frontmatter

## Review Summaries And Catalog

Files:

- `knowledge/80_summaries/team_review_latest.md`
- `knowledge/80_summaries/team_review_digest.md`
- `knowledge/80_summaries/team_review_changelog.md`
- `mcp/catalog.json`

Classification:

- summaries: `derived_summary`
- catalog: `derived_summary`

Producer:

- `scripts/sync_reviews.py`

Consumer:

- agents and humans navigating review state
- MCP-style catalog consumers

Important note:

- the payloads are local-only by policy, but their existence is operationally
  meaningful and must not be treated as throwaway scratch output

## Local-Git Manifests

Files:

- `ops/local_git_manifests/change_sessions.json`
- `ops/local_git_manifests/review_sessions.json`
- `ops/local_git_manifests/knowledge_summaries.json`
- `ops/local_git_manifests/mcp.json`
- `ops/local_git_manifests/pushable_tracked.json`
- `ops/local_git_manifests/index.json`

Classification:

- `protocol_evidence`

Producer:

- `scripts/local_git_guard.py`

Consumer:

- `pre-commit` and `pre-push` hooks
- cleanup audits
- human review of boundary drift

## Service And Watcher Runtime

Repo-local source:

- `systemd/dict-ai-coding-review-sync-watch.service`
- `install-review-sync-user-service.sh`

Runtime outside repo:

- installed user service in `~/.config/systemd/user/`
- systemd logs
- running watcher state

Classification:

- repo-local files: `canonical_source`
- installed service/log state: `runtime_state`

## Future Archive Batch Outputs

If a cleanup batch later archives files, these generated artifacts will appear:

- `archive/worktree_cleanup/<batch>/manifest.json`
- `archive/worktree_cleanup/<batch>/notes.md`

Classification:

- `protocol_evidence`

The archived payload itself is not "new source"; it is a preserved copy of
items moved out of the active worktree and must be interpreted through the
manifest.

## Compiled Noise

Patterns:

- `**/__pycache__/`
- `*.pyc`
- `.pytest_cache/`
- `node_modules/`
- `dist/`
- `build/`

Classification:

- `compiled_noise`

Producer:

- Python interpreter
- test runners
- Node/Bun tooling

Consumer:

- runtime or test acceleration only

These are the safest future archive candidates, but still are not deleted by
default.
